## 420 s fixture — known blocker

The 7-minute run exports both longform masters with `-16.3 LUFS` and correct
48 kHz audio. The Shorts batch then fails the duration gate: FFmpeg renders the
first two video pieces and all six audio pieces into the combined file, so the
video stream is ~14.4 s while the audio is ~26.3 s.

`run_shorts_batch` used to delete the bad file and keep the clip in the
manifest, which hid the failure. It now raises `ExportError` so the gate and
the caller see the broken deliverable. Root cause is still open; it only
reproduces inside the full 7-minute e2e path, not in an isolated re-render of
the same project.
