# Tray Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `videoflow tray`, a single-process tray icon that owns the local Uvicorn service and exposes open/start/stop/restart/status/quit.

**Architecture:** `pystray` runs on the main thread; `ServerSupervisor` owns a Uvicorn `Server` on a daemon worker thread. The tray writes the existing PID file while the service runs and removes it on stop. No display or backend falls back to `videoflow serve`.

**Tech Stack:** Python 3.11+, Uvicorn, pystray, Pillow, argparse.

**Spec:** `docs/superpowers/specs/2026-11-12-tray-icon-design.md`

## Global Constraints

- Optional dependency only: `tray = ["pystray>=0.19", "pillow>=10"]`.
- One process: no child server, no orphan.
- Existing `status`/`stop` PID semantics stay valid.
- Fallback path when `pystray` or the display is missing.
- No release, no packaging change, no UI change.

## Review Focus

- Missing tray backend or display: must fall back, never crash.
- Port already held by a VideoFlow service: replace it, never race.
- Server thread dies at startup: tray stays alive, status becomes stopped.
- Quit while running: server stops and PID file is removed.
- Double start/stop/restart: idempotent, no duplicate thread.
